**Goal:** Give local work its own Neon branch with migrations to production (Phase 0), then add bookings, table plans, per-guest online checkout with a seat hold, and paid online orders becoming seated bookings (Phase 1).

**Architecture:** Pure seating logic lives in `src/lib/seating.ts` (copied in spirit from `StepIn_Old/lib/repository.ts`) and is unit-tested. One server module `src/lib/event-seats.ts` loads an event's tables, live guests and held seats from Payload (always `pagination: false`) and is the only place seats are counted. Bookings are a new collection with guests as an array; online bookings are created by an Orders `afterChange` hook inside the webhook's transaction. Checkout takes a Postgres advisory lock per event.

**Tech Stack:** Payload 3.91, Next.js 16 App Router, Postgres on Neon (`@payloadcms/db-postgres`, drizzle under the hood), Stripe Node SDK 22.6 (API `2026-08-26.dahlia`), Vitest 4, Neon CLI 8.8 (`neon`), Vercel CLI 59.

**Spec:** `docs/superpowers/specs/2026-10-19-venue-management-design.md`

## Global Constraints

- Nothing existing is removed: existing fields, pages and checkout keep working; Orders keep `ticketType`, `quantity`, `amount`.
- Prices come from Payload on the server; money in integer cents; an order is paid only from the signed webhook; a webhook delivered twice never creates two bookings (`CLAUDE.md`).
- Every `payload.find` that feeds a count uses `pagination: false`.
- Currency stays `CURRENCY` from `src/lib/format.ts` (`eur`).
- Seat hold = 30 minutes; Stripe session `expires_at` = order `holdUntil`.
- Quantity per purchase 1–10 (as today).
- Guest statuses exactly: `paid`, `pay_at_venue`, `not_paying`, `cancelled`. Seat-occupying: the first three.
- Table shapes exactly: `long`, `round`, `square`; default `long`. Default seats per table 10 (Settings arrives in Phase 3; use the constant `DEFAULT_SEATS = 10` until then).
- Production database is Neon branch `main`; local and Vercel Preview use branch `dev`. Migrations run against production only from the production build, over `DATABASE_URL_UNPOOLED`.
- One PR for Phase 0 (base `main`), one for Phase 1 (stacked on Phase 0's branch until it merges).

## Review Focus

1. **Payload's default page size of 10**: an event with 11+ bookings must still count every guest. → Task 5 test seeds 12 bookings.
2. **A draft save of an event must not reconcile tables or unseat anyone**; only publishing does. → Task 3 test.
3. **Tampered checkout form** (11 guests, empty names, a ticket id from another event, an unpublished or past event, a non-numeric event id) must be refused with no order created. → Task 7 tests.
4. **Duplicate webhook delivery** (sequential and concurrent) creates exactly one booking and leaves the order paid. → Task 8 test.
5. **Expired holds and empty rooms**: a pending order whose `holdUntil` has passed holds nothing; an event with zero tables has no limit (`seatsAvailable` returns `null`). → Task 2 and Task 5 tests.
